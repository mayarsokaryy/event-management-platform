# Event Management Platform

**Designing a Scalable and Reliable Platform for Event Management**

## Overview

The Event Management Platform is a software engineering project focused on designing a centralized system that simplifies the organization and management of events.

The platform aims to provide a structured way for attendees to discover and participate in events, organizers to manage their events, and administrators to oversee platform activities.

This project emphasizes software architecture, requirements engineering, quality attributes, and architectural decision-making as part of the Principles of Software Architecture course.

## Project Objectives

- Define clear functional and non-functional requirements.
- Identify stakeholders and their concerns.
- Model system boundaries and external interactions.
- Design an architecture that addresses scalability, reliability, security, and maintainability.
- Document architectural decisions and their trade-offs.
- Establish a foundation for a future prototype and implementation.

## User Roles

The proposed platform includes the following roles:

- **Attendee:** Discovers events and participates in the event experience.
- **Organizer:** Creates and manages events.
- **Administrator:** Oversees platform operations and administration.

The final responsibilities and permissions of each role will be refined during requirements analysis.

## Planned Capabilities

The following capabilities are under consideration as part of the system design:

- Event creation and management.
- Event discovery and browsing.
- Attendee registration for events.
- User and role management.
- Event information and availability management.
- Integration with an external payment gateway, if required by the final requirements.

These capabilities are subject to refinement and prioritization during requirements engineering.

## Architecture and Design

The project follows a requirements-driven architectural design process.

The architecture work includes:

- **System Overview:** Defining the system's purpose, scope, and boundaries.
- **Stakeholder Analysis:** Identifying stakeholders, their concerns, and architectural implications.
- **C4 Context Diagram:** Illustrating the system, its users, and external dependencies.
- **Functional Requirements:** Documenting and prioritizing requirements using the MoSCoW method.
- **Quality Attribute Scenarios:** Defining measurable expectations for attributes such as performance, security, reliability, and maintainability.
- **Architecturally Significant Requirements (ASRs):** Identifying and prioritizing requirements that influence architectural decisions.
- **Architectural Decisions:** Documenting design choices, their rationale, and trade-offs as the project evolves.
